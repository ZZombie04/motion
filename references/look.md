# 룩 — 고급스러워 보이는 화면의 규칙

고급스러움은 장식이 아니라 **절제와 정밀함**에서 나온다: 색은 적게, 글자는 크게와 작게만, 여백은 넉넉하게, 빛은 은은하게, 정렬은 칼같이.

## 1. "아마추어 티"가 나는 이유와 바꾸는 법

| 이렇게 하면 유치해진다 | 이렇게 바꾼다 |
|---|---|
| 색을 여러 개 쓴다(무지개·그라디언트 글자) | 바탕 + 글자 + 회색 2단계 + **포인트 한 색**. 포인트는 한 프레임에 한 곳 |
| 만화풍 일러스트·클립아트·이모지 | 타이포·도형·UI·선 아이콘(`data-icon`)·사진. 사물은 픽토그램 수준까지만 |
| 모든 요소가 통통 튄다 | 튕김은 칩·점·버튼만. 제목·카드·카메라는 `mo.out`으로 조용히 감속 |
| 페이드 인/아웃만 쓴다 | 제목은 마스크 리빌, 요소는 스태거, 장면은 공유 요소로 잇는다 |
| 전부 가운데 정렬, 크기가 비슷하다 | 큰 것 하나 + 작은 것 여럿. 크기 대비 4배 이상(제목 13u vs 라벨 2u) |
| 화면을 가득 채운다 | 내용은 화면의 40–60%. 나머지는 여백(빛과 그레인이 채운다) |
| 평평한 단색 배경 | 조명(`stagelight`)·지평선 빛(`horizon`)·점 격자 + 그레인 + 비네트 |
| 진한 테두리·딱딱한 그림자 | 1px 헤어라인(`--line`) + 위쪽 하이라이트 + 여러 겹의 부드러운 그림자(`mo-card`가 이미 그렇다) |
| 글자가 작고 가장자리에 붙는다 | 본문 3u 이상, 좌우 `--safe-x` 안쪽, 쇼츠는 상 10.5%·하 20% 비움 |
| 일정한 속도, 동시에 등장 | 빠르게 나와 길게 감속, 0.05–0.1초씩 어긋나게 |
| 화면이 멈춰 있다 | `cam.drift`로 끝까지 아주 느리게 다가간다 |
| 글꼴이 여러 개 | Pretendard 하나 + (숫자·영문 Geist) + (라벨 Geist Mono) + (감성 한 단어 Instrument Serif) |
| 실제 서비스 로고·UI를 흉내 낸다 | 로고 없는 일반화된 UI. 버튼·입력창·카드의 원형만 |
| UI 크롬에 그라디언트·광택 | 평면 + 헤어라인 + 그림자. 그라디언트는 배경의 빛에만 |
| 아이콘 굵기가 제각각 | 한 세트(`data-icon`), 한 굵기(`data-stroke`) |
| 아무 일도 없는 죽은 시간 | 3초 안에 다음 비트. 홀드에도 드리프트·떠 있기 |
| 아무 데나 입자 폭발·글로 | 결정적인 순간 한 번(축하·공개). 나머지는 빛 한 겹 |
| 소리를 모든 등장에 붙인다 | 큰 움직임 4–8곳만. 조용한 등장이 있어야 소리가 산다 |

## 2. 테마와 색

| 테마 | 바탕 / 글자 | 성격 | 잘 맞는 포인트 |
|---|---|---|---|
| `ink` | #09090B / #F5F5F7 | 기본. 테크·제품·AI·키노트 | blue cyan mint lime amber orange |
| `night` | #060914 / #EEF2FF | 차갑고 깊다. 데이터·금융·감성 | mint amber cyan violet |
| `paper` | #F3F3F5 / #0B0B0D | 차분한 문서·교육·공공 | blue red orange violet |
| `white` | #FFFFFF / #0B0B0D | 제품 사진 같은 밝음. 생활·학생 | blue pink orange mint |
| `pop` | 포인트 색 / 그 위 글자색 | 박자 컷·강조 한 장면 | — |

- 회색은 토큰만: 보조 글자 `--fg-2`, 라벨 `--fg-3`, 비활성 `--fg-4`, 선 `--line`. 임의의 회색 hex를 새로 만들지 않는다.
- 포인트 색을 쓰는 곳 후보(하나만): 형광펜, 주요 버튼, 진행 막대, 상태 점, 선택 테두리(`mo-ring`), 차트의 한 막대.
- 배경의 빛(`horizon`·`glow`·`aurora`)이 포인트 색을 띠는 것은 괜찮다 — 그것은 분위기이지 요소가 아니다.
- 브랜드 색을 받았으면 `data-accent="#hex"`. 두 가지 색을 받았으면 하나는 포인트, 하나는 `data-accent2`(빛에만).
- 테마 반전(검정 ↔ pop ↔ paper)은 박자 컷에서 가장 강한 무기다. 한 영상에 반전은 2–4번.

## 3. 타이포그래피

| 클래스 | 크기 | 쓰임 |
|---|---|---|
| `mo-display` | 13.2u · 굵기 720 · 자간 −0.04em | 화면의 주인공. 한 화면에 하나 |
| `mo-h1` | 9.2u | 제목 |
| `mo-h2` | 6.4u | 부제·질문 |
| `mo-h3` | 4.5u | 카드 제목 |
| `mo-body` | 3.3u · `--fg-2` | 설명 한두 줄 |
| `mo-small` | 2.6u | 캡션 |
| `mo-label` | 2.0u · 모노 · 대문자 · 자간 0.14em · `--fg-3` | 메타 정보, 번호, 상태 |
| `mo-stat-num` | 15u · Geist | 큰 숫자(더 키워도 된다: 30–45u) |

- **크게 아니면 작게.** 중간 크기 글자를 여러 개 두지 않는다. 제목 하나를 과감히 키우고 나머지는 라벨 수준으로.
- 한글 제목은 줄 간격 1.08–1.16, 자간 −0.03em 안팎(클래스 기본값). 줄바꿈은 의미 단위로 직접 `<br>`.
- 숫자·영문 대문자는 `mo-latin`(Geist)로 — 한글과 섞일 때 숫자가 또렷해진다. 변하는 숫자는 자동으로 고정폭.
- 단위는 숫자의 1/4 크기로 오른쪽 아래(`<small>`).
- 강조는 **한 가지 방법만**: 형광펜 *또는* 포인트 색 글자 *또는* 세리프 이탤릭. 겹쳐 쓰지 않는다.
- 세리프(`mo-serif`)는 라틴 전용 — 영문 한두 단어의 감성 포인트(예: *flow*, *since 2026*)에만.
- 외곽선 글자(`mo-outline`)는 배경 질감으로만(읽히는 본문 금지).
- 모서리 라벨(HUD): 좌상 프로젝트명, 우상 번호/날짜 정도. 영상에 "디자인된" 인상을 준다. 쇼츠에서는 2.1u 이상.
- 모노 라벨은 영문·숫자가 기본이다. 한글이 섞이면 그 글자만 Pretendard로 그려진다(번들 모노에는 한글이 없다) — 한글 라벨은 `mo-small`에 `--fg-3`을 쓰는 편이 고르다.

## 4. 구도

- **여백**: 좌우 `--safe-x`(7.4%, 쇼츠 8%). 쇼츠는 상단 10.5%·하단 20%가 앱 UI에 가려진다 → 핵심은 그 사이(대략 화면 높이의 12–78%).
- **무게 중심**: 세로 화면은 정중앙보다 살짝 위(30–60% 높이)에 주인공. 아래 1/4은 빛(지평선)에게 준다.
- **정렬 축 하나**: 한 장면은 왼쪽 정렬 *또는* 가운데 정렬 중 하나로 통일. 섞으면 어수선하다.
- **묶음**: 라벨–제목–보조를 한 덩어리로 붙이고(간격 2–3u), 덩어리와 덩어리 사이는 멀리(8u+).
- **반경**: 큰 카드 `--r-xl`·`--r-lg`, 안쪽 요소는 더 작게, 버튼·칩은 알약. 중첩될수록 반경이 줄어야 한다.
- **가로 화면(16:9)**: 좌 55% 글자 / 우 45% 대상, 또는 중앙 대칭. 아래위 8% 비움.
- **숫자 장면**: 세로 화면은 숫자가 폭의 55–80%. **가로 화면은 폭이 아니라 높이의 35–50%**로 잡는다(폭에 맞추면 위아래가 넘친다). 라벨은 위, 해석 한 줄은 아래. 단어를 정확한 폭에 맞출 땐 `M.fitText`.

## 5. 빛과 깊이

배경은 "색"이 아니라 **조명**으로 생각한다.

| 조합 | 인상 | 마크업 |
|---|---|---|
| 스튜디오 | 중립·제품 | `mo-stagelight` |
| 지평선 | 키노트·테크·웅장 | `mo-stagelight` + `mo-dotgrid` + `mo-horizon` |
| 웅덩이 빛 | 대상 뒤의 후광 | `mo-glow`(초점 뒤에 하나) |
| 설계도 | 구조·데이터 | `mo-gridlines`(옅게) + `mo-spot` |
| 원근 바닥 | 공간감·기기 | `mo-floor` + `mo-glow` |
| 오로라 | 감성·AI | `M.aurora({ spread: 'bottom' })` — 색 2개 이하, 과하면 흔한 "AI 그라디언트"가 된다 |
| 밝은 스튜디오 | 흰 테마 | `mo-stagelight`만(아주 옅음) + 카드 그림자 |

- 항상: `M.grain()`(질감 + 밴딩 방지), 어두운 테마에 `mo-vignette`.
- 박자 컷처럼 면 전체를 색으로 쓰는 장면도 "평면"은 아니다 — 그레인과 아주 옅은 `mo-stagelight`는 남긴다. 빼는 것은 격자·지평선 같은 **무늬**다.
- 깊이는 세 가지로 만든다: ① 3D 기울임(카메라 `rx/ry` 3–10°) ② 레이어(`mo-layer data-z`) ③ 그림자·유리(`mo-card`·`mo-glass`·`mo-lift`).
- 유리(`mo-glass`)는 뒤에 빛이 있을 때만 의미가 있다. 검은 바탕 위에서는 `mo-card`.
- 하이라이트 순간에 빛을 한 번 움직인다: 카드 위 `mo-sheen`(`--sheen` −0.3 → 1.3), 지평선 `filter: brightness(1 → 1.5 → 1.15)`, 장 바꿈의 빛샘 `M.leak`, 공개 뒤 천천히 도는 빛살 `M.rays`.
- 실제 3D(`M.three`)는 제품 사진처럼: 키 라이트(위 앞) + 림 라이트(뒤, 포인트 색 쪽으로 살짝) + 아주 약한 채움. 재질은 금속성 0.4–0.7, 거칠기 0.2–0.4. 배경은 테마 색 그대로 두고 그 위에 `mo-glow` 하나.

## 6. UI를 그릴 때

- 기기 틀 없이 화면 속 UI만 보여 주는 편이 대부분 더 깔끔하다(인서트). 기기는 "폰/노트북이라는 사실"이 메시지일 때만.
- UI는 **진짜처럼 구체적으로, 그러나 최소한으로**: 입력창 하나, 버튼 하나, 줄 3개. 메뉴·사이드바를 다 그리지 않는다.
- 상태 변화가 생명이다: 플레이스홀더 → 입력 → 버튼 활성(색 변화) → 눌림 → 스피너 → 체크. 각 단계가 0.2–0.6초.
- 줄 높이·간격은 넉넉히(항목 패딩 2.5u+). 화면 속 글자도 3.4u 이상이어야 폰에서 읽힌다.
- 결과 수치가 예시면 `(예시)`를 작은 라벨로 붙인다.

## 7. 화면 비율별 메모

| 비율 | 핵심 |
|---|---|
| 9:16 쇼츠 | 큰 글자 2줄, 요소는 세로로 쌓는다, 하단 20% 비움, 기기는 폰 |
| 16:9 | 좌우 분할, 카메라의 옆 이동·오빗이 잘 산다, 기기는 노트북 |
| 1:1 · 4:5 | 가운데 대칭, 한 장면 한 요소 |
| 1080×830 인서트 | 영상 본문 위에 얹는 컷. 사방 여백을 6%로 줄이고 UI를 크게 |
| 투명 오버레이 | `--alpha`로 내보낼 자막바·로워서드. 배경·그레인·비네트를 넣지 않는다 |
| 2.39:1 시네마 | `cinema`(1920×804). 넓은 여백, 느린 카메라, 세리프 한 단어. 레터박스 없이 화면 자체가 넓다 |
