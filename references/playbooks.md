# 플레이북 — 영상 종류별 작업 흐름

요청을 받으면 먼저 **어떤 종류의 영상인지** 하나 고른다. 종류마다 시작 템플릿, 먼저 받을 재료, 연출의 핵심, 합격 기준이 다르다.
종류를 고르는 데 질문하지 않는다. 요청의 동사와 쓰임새에서 정한다(`motion brief`가 후보를 준다).

| 요청에 보이는 말 | 플레이북 | 시작 템플릿 |
|---|---|---|
| 홍보·모집·연수 안내·오프닝·쇼츠 | A 홍보 쇼츠 | `hook` · `beat` |
| 앱·서비스·제품·사이트 소개, 출시, "우리 사이트로" | B 제품·사이트 소개 | `launch` (+ `motion brand`) |
| 설명·방법·강의·내레이션·"말하면서" | C 설명(내레이션·자막) | `captions` |
| 수치·성과·결과 보고·통계·발표 화면 | D 데이터 | `data` |
| 음악·노래·박자·댄스·키네틱 | E 음악에 맞춘 영상 | `beat` |
| 화면 시연·기능 소개·"이렇게 쓰면" | F UI 시연 | `ui` |
| 로고·채널 엔딩·인트로 3–5초 | G 로고·스팅 | `samples/06-logo-sting.html` |
| 자막바·이름표·영상 위에 얹을 것 | H 오버레이 | `lowerthird` |
| 반복·GIF·배경·스티커 | I 루프 | `loop` |
| 3D·오브젝트·제품 히어로 | J 3D 히어로 | `hero3d` |
| "이 영상처럼", 참고 영상 첨부 | K 레퍼런스 따라 하기 | 분석 결과에 맞는 것 |
| 학생별·반별·상품별로 여러 편 | L 여러 편 | 위 템플릿 + `motion batch` |

어느 것이든 마지막은 같다: `check` 오류 0 → `score` 85점 이상 → 시트를 **직접 보고** 고친다 → `render` → 결과 프레임 띠까지 확인.

---

## A 홍보 쇼츠

- **재료**: 행사·과정 이름, 날짜·장소, 신청 방법. 없으면 지어내지 않고 자리를 비운다.
- **구조**(10–16초): 0초 훅(숫자·질문, 이미 움직이는 중) → 해결/약속 → 증거 하나(숫자 카운트, 체크리스트) → 엔드카드(제목 2줄 + 행동 하나).
- **연출**: 비스듬한 화면이 정면으로 정착하는 훅, 같은 물체가 끝까지 이어지는 전환, 엔드카드에서 커서 클릭.
- **소리**: 음악이 있으면 강박에 컷. 효과음 4–6개(훅 whoosh, 체크 success, 엔드카드 click).
- **합격**: 0초 프레임이 포스터로 쓸 만하다 · 엔드카드 2초 이상 · 날짜·이름이 한 글자도 틀리지 않았다.

## B 제품·사이트 소개

- **재료**: 사이트 주소가 있으면 먼저 `motion brand https://…` → brand.json(색·글꼴·로고·문구). 없으면 이름과 한 줄 설명.
- **시작**: `motion new launch.html --template launch --brand brand/brand.json`.
- **구조**(12–20초): 훅 한 줄 → 이름 공개(로고가 있으면 로고, 없으면 워드마크) → 기기 화면 속 UI와 기능 주석 2–3개(카메라가 옮겨 다님) → 핵심 이점 숫자 하나 → 행동 유도(주소).
- **연출**: 기기는 3/4 각도에서 정면으로 돌아서고, 기능마다 카메라가 그 부분으로 다가간다. 주석은 `M.callout`.
- **합격**: 사이트에 없는 수치·인증·고객사를 만들지 않았다 · 실제 서비스 UI를 베끼지 않고 일반화했다 · 로고가 찌그러지지 않았다.

## C 설명(내레이션·자막)

- **재료**: 대본(없으면 사용자의 말을 화면용 대본 4–8문장으로 줄여 보여 주고 진행). 녹음이 있으면 녹음 파일.
- **시간**: 녹음 전이면 `motion captions plan 대본.txt`, 녹음이 있으면 `motion captions align 대본.txt voice.wav`. 이 시각들이 비트 시트다.
- **시작**: `motion new explain.html --template captions`, 자막 파일을 옆에 두고 `data-captions`를 바꾼다.
- **연출**: 문장마다 그림 하나(큰 핵심어, 숫자, 도식, 아이콘)가 말보다 0.3초 먼저 바뀐다. 위 1/3은 그림, 아래는 자막.
- **소리**: `<audio data-role="voice">`. 음악은 깔아도 30% 아래(덕킹이 자동).
- **합격**: 자막과 다른 글자가 겹치지 않는다 · 문장마다 화면이 바뀐다 · 말이 끝나고 0.8초 이상 엔드카드.

## D 데이터

- **재료**: 수치와 그 단위·기간·출처. 받지 않은 비교 대상(전년 등)은 붙이지 않는다.
- **시작**: `--template data`. 값은 `--vars "values=…&labels=…"`로 바꾼다.
- **구조**: 질문 → 같은 자리에서 A가 B로(카운트 + 같은 감속의 막대·도넛) → 주석 하나 → 해석 한 줄 → 홀드.
- **연출**: 차트는 `M.chart`, 강조는 하나만 포인트 색, 나머지는 회색. 숫자는 Geist.
- **합격**: 숫자와 단위가 겹치지 않는다 · 결과 숫자가 1.2초 이상 정지 · 예시 수치는 "(예시)".

## E 음악에 맞춘 영상

- **재료**: 음악 파일. 먼저 `motion audio 노래.mp3`로 BPM·박·마디 확인. 음악이 없으면 `data-bpm`으로 짜 두고 나중에 넣는다.
- **시작**: `--template beat`, `<audio src="노래.mp3" data-start="0">`를 넣으면 `M.grid()`와 `b8` 토큰이 노래를 따른다.
- **연출**: 마디 첫 박에 큰 변화(테마 반전·전환), 박마다 단어, 반박에 작은 디테일. 음악 세기(`low`)는 배경 빛에만.
- **검수**: `motion sheet 파일 --beats music`(박마다 한 장)으로 박 위의 그림을 하나씩 본다.
- **합격**: 컷이 박에서 ±1프레임 안 · 같은 박 패턴이 3마디 넘게 반복되지 않는다 · 끝 마디는 홀드.

## F UI 시연

- **시작**: `--template ui`(인서트 1080×830) 또는 기기 안 화면.
- **연출**: 원인→결과. 커서가 누르면 버튼이 눌리고 결과가 나온다(`cur.click` + `M.press` 같은 시각). 입력은 `M.type`(한글 자모). 화면을 꽉 채우는 장면에서는 오토 줌으로 커서가 갈 곳을 먼저 보여 준다.
- **소리**: click, key(타이핑), success.
- **합격**: 커서가 실제로 버튼 위에 있다(`motion frames`로 확인) · 끝 상태 0.8초 이상 정지.

## G 로고·스팅

- **재료**: 로고 파일(SVG가 가장 좋다). 없으면 이름 워드마크.
- **연출**: 점 하나 → 선/원 → 로고(`M.morphPath`로 도형이 로고 윤곽이 되게), 3–5초, 마지막 1.5초 홀드. 효과음은 착지 하나(`drop`·`impact`)와 반짝임(`sparkle`) 정도.
- **합격**: 로고 비율·색이 원본 그대로 · 첫 프레임이 완전히 검지 않다(점이라도).

## H 오버레이

- **시작**: `--template lowerthird`(무대에 `data-overlay`). 렌더는 `--format mov --alpha`(편집 프로그램에 얹는 투명 영상).
- **원칙**: 배경·그레인·비네트 없음. 들어오고 나가는 것이 깨끗해야 한다(이름표는 `M.lowerThird`).
- **합격**: 투명 영역 알파가 0 · 글자 가장자리가 깨끗하다(`motion frames`로 확대 확인).

## I 루프

- **시작**: `--template loop`. 무대에 `data-loop`.
- **원칙**: 모든 움직임의 주기가 영상 길이를 나누어 떨어지게(6초 영상이면 1·2·3·6초). 카메라 드리프트 금지(한 방향으로만 가므로). 끝 = 시작.
- **검수**: `check`가 마지막 프레임과 첫 프레임을 비교한다. GIF는 `--format gif`.

## J 3D 히어로

- **시작**: `--template hero3d`. 3D는 `M.three`가 그린다(실제 WebGL).
- **원칙**: 제품 사진처럼 — 키 라이트 + 림 라이트 + 은은한 채움, 배경은 그라디언트 한 겹. 회전은 느리게(초당 20–40도), 카메라는 한 방향으로 길게. 글자는 3D 옆 여백에 마스크 리빌.
- **합격**: 3D 가장자리가 계단지지 않는다 · 물체가 화면 밖으로 잘리지 않는다 · 모든 움직임이 t의 함수.

## K 레퍼런스 따라 하기

1. `motion analyze 참고.mp4` → 컷 리듬·움직임·색·BPM과 샷 시트. 시트를 직접 보고 구도·타이포·전환을 말로 적는다.
2. 트리트먼트에 **옮길 것**(속도, 컷 길이, 화면 구성 방식, 색의 온도)과 **바꿀 것**(문구, 이미지, 로고 — 원본을 베끼지 않는다)을 나눠 적는다.
3. 분석이 제안한 BPM·테마·포인트 색으로 시작한다. 같은 노래가 있으면 `<audio>`로.
- **합격**: 분석의 평균 샷 길이와 우리 영상의 장면 길이가 비슷하다 · 원본의 문구·이미지가 하나도 없다.

## L 여러 편(개인화)

- 한 편을 완성한 뒤 바뀌는 부분을 `data-var`/`M.var`로 바꾼다 → `motion vars 파일`로 확인 → 표(CSV)를 만든다(열 이름 = 변수 이름) → `motion batch 파일 --data rows.csv --name "{이름}"`.
- **합격**: 가장 긴 이름·문구로 한 편을 먼저 렌더해 넘치지 않는지 본다(`--vars`로 최악의 행).

---

## 제안이 필요할 때

사용자가 "몇 가지 안을 보여 줘"라고 하면 만들기 전에 **서로 다른 안 2–3개**를 3줄씩 보여 준다(로그라인 · 룩 · 결정적 장면). 그렇지 않으면 하나를 골라 바로 만든다 — 묻느라 멈추지 않는다.
