# 감독 노트 — 요청을 연출로 바꾸는 법(리프롬프트)

사용자는 "AI 연수 홍보 쇼츠 만들어줘"처럼 **무엇**만 말한다. **어떻게**(구조·카메라·타이포·전환·리듬·색)는 전부 감독이 정한다.
코드를 쓰기 전에 반드시 이 문서의 순서로 **트리트먼트**를 먼저 쓴다. 트리트먼트가 좋으면 코드는 받아쓰기다.

## 1. 원칙 일곱 가지

1. **한 영상 = 한 문장.** 보고 난 사람이 한 문장으로 말할 수 있어야 한다. 두 가지를 말하려면 두 편으로 나눈다.
2. **말하지 말고 보여 준다.** "빠르다"를 쓰지 말고 120이 10으로 줄어드는 것을 보여 준다. 글자는 화면이 한 일을 확정하는 데만 쓴다.
3. **원인이 보이고 결과가 보인다.** 커서가 누른다 → 버튼이 눌린다 → 결과가 나온다. 저절로 일어나는 일은 가짜처럼 보인다.
4. **같은 물체가 이어진다.** 장면이 바뀌어도 무언가 하나(도형·숫자·선·점)는 살아남아 다음 장면의 일부가 된다. 컷이 아니라 변신.
5. **한 비트에 초점 하나.** 동시에 두 곳을 보게 하지 않는다. 포인트 색도 한 프레임에 한 곳.
6. **멈추지 않되, 읽을 시간은 준다.** 카메라는 늘 아주 천천히 움직이고, 핵심은 0.8–1.2초 이상 제자리에 머문다.
7. **덜어 낸다.** 요소 하나를 더할 때마다 나머지가 약해진다. 색 하나, 글꼴 하나(+강조용 하나), 움직임의 성격 하나.

## 2. 브리프 뽑기

요청에서 일곱 칸을 채운다. **비어 있는 칸은 묻지 않고 정한다.** 질문은 "메시지 자체를 알 수 없을 때"에만 한 번.
`motion brief "요청 문장"`(MCP `motion_brief`)이 이 표의 기본값과 §5의 연출 후보를 채운 초안을 준다 — 그대로 쓰지 말고 감독으로서 다듬는다.

| 칸 | 질문 | 비었을 때 |
|---|---|---|
| 목적 | 훅 / 설명 / 시연 / 증명(수치) / 브랜드 / 전환 / 축하 | 요청의 동사에서 추정("홍보" → 훅+증명, "소개" → 설명, "인트로" → 브랜드) |
| 메시지 | 보고 나서 남아야 할 한 문장 | 사용자의 말에서 가장 구체적인 명사+변화로 직접 쓴다 |
| 대상·맥락 | 누가 어디서 보나 | 쇼츠라면 소리 없이·엄지로 넘기는 사람 |
| 화면 | 비율·해상도 | 쇼츠·릴스·틱톡·세로 → 1080×1920 / 유튜브·발표·가로 → 1920×1080 / 피드 → 1080×1080·1080×1350 / 본문 인서트 → 1080×830 |
| 길이 | 초 | 스팅 3–5 · 인서트 5–8 · 홍보·인트로 10–16 · 설명 20–40 |
| 톤 | 형용사 2개 | 분야에서 추정(§6 룩 표) |
| 필수 요소 | 꼭 들어갈 문구·이름·날짜·수치·색 | 사용자가 준 것만. **없는 사실·수치·로고는 만들지 않는다**(필요하면 "예시"로 표시) |

## 3. 메시지를 '변화'로 바꾸기

모션그래픽은 **상태 A가 상태 B로 변하는 것**이다. 메시지에서 변화의 동사를 찾고, 그 동사를 화면의 물리적 움직임으로 옮긴다.

| 메시지의 뜻 | 화면의 동사 | 구현 |
|---|---|---|
| 줄어든다·빨라진다 | 숫자가 내려가고 막대가 줄어든다 | `M.count` 내림 + `M.fill` 줄임 |
| 늘어난다·성장한다 | 숫자가 구르며 오르고 선·막대가 자란다 | `M.odometer`, `grow`, `draw` |
| 한 번에 끝난다 | 한 줄 입력 → 여러 줄이 차례로 완료 | 타이핑 → 체크리스트 |
| 모인다·하나가 된다 | 흩어진 조각이 한 점/한 줄로 수렴 | 여러 요소 → 같은 좌표로 트윈 |
| 펼쳐진다·종류가 많다 | 하나가 부채꼴·격자로 갈라진다 | 스태거 + 3D 틸트 |
| 드러난다·알고 보니 | 꽉 찬 화면에서 물러나면 더 큰 맥락 | 풀백 리빌(`cam.to zoom↓`) |
| 깊이 들어간다 | 요소 안으로 뚫고 들어가 다음 장면 | 줌 스루(`transition zoom`, 글자 구멍 통과) |
| 바뀐다(전/후) | 띠가 쓸고 지나가며 화면이 바뀐다 | `transition wipe`, 테마 반전 |
| 고른다·집중한다 | 여럿 중 하나만 들려 오르고 나머지는 어두워진다 | 스포트라이트 리프트 + 랙 포커스 |
| 이어진다·흐른다 | 선을 따라 점이 이동한다 | `draw` + `M.follow` |
| 박자·흥 | 음악의 박마다 단어·컷, 저음에 맞춰 빛이 숨 쉰다 | `<audio>` + `M.grid()` + `music.low(t)` |
| 말하다·설명하다 | 말에 맞춰 단어가 켜지고 문장마다 그림이 바뀐다 | `M.captions` + 문장 시각에 맞춘 장면 |
| 형태가 바뀐다·진화한다 | 한 도형이 다른 도형·로고가 된다 | `M.morphPath` + `M.shape` |
| 실물·입체 | 빛을 받은 오브젝트가 천천히 돈다 | `M.three` |
| 시작된다 | 점 하나가 켜지고 커져 화면이 된다 | 점 → 원 → 카드 변신 |
| 약속·신뢰 | 흔들림 없이 천천히 다가가며 한 줄이 놓인다 | 느린 푸시 인 + `rise` |

로그라인은 이 동사로 쓴다: **"[주체]가 [동사]해 [결과]가 된다."**
예) "입력창의 한 줄이 카드로 자라 세 단계가 끝나고, 그 진행 막대가 120분을 10분으로 줄인다."

## 4. 구조 — 길이별 비트 시트

시간은 **절대 시각**으로 적는다. 각 비트에는 화면에 보이는 문구를 "따옴표"로 그대로 쓴다.

**3–5초 스팅**(로고·전환·한 단어)
```
0.0–0.6  타격   가장 작은 요소 하나가 톡 나타난다(점·선·글자 한 자)
0.6–2.2  전개   그 요소에서 전체가 자라난다(마스크·그리기)
2.2–끝   정착   이름/한 줄이 놓이고 아주 느리게 다가간다
```

**5–8초 인서트**(한 가지 요점 — 영상 본문에 끼워 넣는 컷)
```
0.0–1.0  제시   입력 상태를 읽을 수 있게(무엇에서 시작하는지)
1.0–3.2  조작   커서·타이핑·드래그 등 원인이 되는 동작
3.2–5.4  결과   같은 물체가 결과로 변한다
5.4–끝   유지   끝 상태 라벨(예: "CONNECTED → RUN")을 0.8초 이상 정지
```

**10–16초 홍보·인트로**(쇼츠의 기본형)
```
0.0–2.5   훅       첫 프레임부터 움직이는 숫자/질문. 화면이 비스듬히 있다가 정면으로 정착
2.5–6.0   전개 1   해결책이 등장하고 사용자의 한 번의 행동(입력·탭)
6.0–9.0   전개 2   그 행동의 결과가 단계적으로 완료
9.0–12.0  증명     숫자 하나로 요약(카운트 + 막대)
12.0–끝   엔드카드  제목 2줄 + 행동 유도 하나. 마지막 1초는 그대로
```

**20–40초 설명**
```
도입(3초) → 문제(4–6초) → 방법 1·2·3(각 4–6초, 같은 틀 반복하며 번호만 바뀜) → 요약(4초) → 엔드카드(3초)
```
반복 구간은 **같은 레이아웃·같은 전환**을 써서 리듬을 만든다. 속도는 빠름–느림–빠름으로 굴곡을 준다.
단계들은 장면을 갈아 끼우지 말고 **옆으로 긴 한 세계**에 나란히 놓아 카메라가 지나가게 하고, 요약에서 물러나 전부를 한 화면에 모은다(레시피 23, `samples/05-three-steps.html`).

**박자 영상**(음악에 맞추는 타이포)
BPM을 정하고(120 = 한 박 0.5초, 128 = 0.469초, 96 = 0.625초) 컷·단어·타격을 박에 놓는다: `const b = M.beats(128)`.
한 박에 단어 하나, 4박마다 배경 반전, 마지막 4박은 홀드.

## 5. 의도 → 기법 선택표

사용자가 기법을 말하지 않는다고 가정하고, 아래에서 **장면마다 한 줄씩** 고른다.

### 5.1 첫 장면(훅)

| 상황 | 연출 | 왜 |
|---|---|---|
| 수치가 있다 | 화면을 꽉 채우는 숫자가 마스크에서 솟는다(0초에 이미 30% 올라온 상태) + 작은 설명 라벨 | 숫자는 0.3초 안에 읽힌다 |
| 질문·통념이 있다 | 두 줄 헤드라인 `rise` + 핵심어 형광펜 | 질문은 넘기는 손을 멈춘다 |
| 제품·화면이 주인공 | 기기가 뒤/비스듬한 각도에서 정면으로 돌아선다 | 사물의 등장은 회전이 가장 고급스럽다 |
| 행사·에너지 | 박자마다 단어 슬램 + 배경 반전 | 리듬이 훅이다 |
| 정적·격조 | 검은 화면의 점 하나 → 선 → 제목 | 비움이 주목을 만든다 |

훅에는 카메라 **정착**(`cam.set({ rx: 9, ry: -12, zoom: 1.15 })` → 2초에 걸쳐 0으로)을 겹치면 평면 글자도 입체로 느껴진다.

### 5.2 카메라

| 의도 | 움직임 | 값의 감 |
|---|---|---|
| 중요하다·집중 | 푸시 인 | `zoom 1 → 1.12–1.25`, 1.4–2.2초 |
| 맥락 공개·반전 | 풀백 | `zoom 2.6 → 1` + `ry` 살짝, 2초 |
| 사물의 입체감 | 오빗 | `ry −8 → 6`, `rx 2–4`, 2–3초 내내 |
| 나열·비교 | 트럭(옆 이동) | `x`를 한 번에 길게, 레이어에 깊이 차 |
| 넘어가기(에너지) | 휩 팬 | 0.4–0.5초, `transition whip` |
| 화면 속으로 | 줌 스루 | 대상의 한 점을 `transformOrigin`으로 12–16배, `power3.in` |
| 고급스러운 초점 이동 | 랙 포커스 | `aperture 2–3`, `focus`를 앞↔뒤 레이어로 0.8초 |
| 전체 구조 | 탑다운 아이소 | `rx 52, rz −28`에서 시작해 정면으로 |
| 긴 화면 훑기 | 슬랜트 돌리 | `rx 28, rz −8` 상태로 `y` 이동 후 정면 |
| 조작 따라가기 | 오토 줌 | 커서가 갈 곳으로 `lookAt zoom 1.4–1.6`, 커서보다 0.1초 늦게 |
| 마무리 | 정면 정착 + 드리프트 | `cam.home` 후 그대로 |

규칙: **한 장면에 카메라 무브 하나.** 장면이 끝나면 다음 무브로 **이어 붙인다**(멈췄다 다시 출발하지 않는다). `cam.drift`는 처음부터 끝까지 항상.

### 5.3 글자

| 문구의 성격 | 처리 |
|---|---|
| 제목(1–2줄) | `rise`(줄 마스크). 핵심어 하나에 형광펜 또는 세리프 이탤릭 |
| 한 줄 선언 | `words` |
| 짧은 영문·숫자 | `chars` 또는 숫자는 `odometer`/`count` |
| 박자 단어 | `slam` + 하드컷 |
| 설명 한 줄 | `fade`(제목보다 0.3–0.5초 뒤) |
| 메타 정보(날짜·번호) | `mo-label` + `scramble` 또는 `fade` |
| 입력하는 글 | `M.type`(한글 자모 조합) |
| AI 답변 | `M.stream` |
| 배경 질감용 글자 | `mo-outline` + `M.marquee`(반드시 `data-deco`) |

### 5.4 전환

| 앞뒤 관계 | 전환 |
|---|---|
| 같은 대상의 다음 단계 | **공유 요소 변신**(`M.morph`, 크기·위치·반경 트윈) — 1순위 |
| 안으로 들어감 | 줌 스루 |
| 전/후, 문제/해결 | 포인트 색 `wipe` 또는 테마 반전 컷 |
| 한 점에서 시작 | `iris` |
| 옆의 다른 항목 | `push` / `whip` |
| 나열된 단계(1·2·3) | 한 세계 안에서 카메라 **트럭**으로 옮겨 가고 끝에 풀백(컷 없음) |
| 카드·기기의 뒷면 | `flip` |
| 음악의 박 | `cut` |
| 리듬감 있는 정보 넘기기 | `slide` · `blinds` |
| 시간·순서·차례 | `clock` |
| 감정·회상·장 바꿈 | `blur` · `leak` |
| 테크·오류·디지털 | `glitch` |
| 결과 공개·박자 타격 | `flash` |
| 꿈·변신 강조 | `warp` |
| 아무 관계 없음 | 장면을 합치지 말고 영상을 나눈다 |

크로스페이드는 마지막 수단이다(관계를 설명하지 못한다).

### 5.5 결과·증명

| 보여 줄 것 | 연출 |
|---|---|
| 단일 수치 | 큰 숫자 `count`/`odometer` + 같은 이징의 막대/링 + 착지 `pulse` + 한 줄 해석 |
| 전후 비교 | 같은 자리에서 A가 B로 변한다(120 → 10). 나란히 놓지 않는다 |
| 여러 항목 완료 | 체크리스트: 스피너 → 체크, 글자 밝아짐, 소요 시간 붙음, 진행 막대 |
| 추세 | 선이 그려지고 마지막 점에 라벨 |
| 구성 비율 | 막대가 차례로 자라고 하나만 포인트 색(`M.chart` column·bar·donut) |
| 숫자 하나의 의미 | 숫자 옆에 점·선·라벨 주석 하나(`M.callout`) |

## 6. 룩 고르기(요약 — 상세는 look.md)

| 톤·분야 | 테마 | 포인트 | 배경 빛 | 글자 |
|---|---|---|---|---|
| 테크·AI·제품 | `ink` | blue / cyan | `stagelight` + `horizon` | Pretendard 굵게 + 모노 라벨 |
| 교육·공공·안내 | `paper` 또는 `white` | blue / mint | `stagelight`(옅게) | Pretendard, 넉넉한 여백 |
| 행사·스포츠·홍보 | `ink` ↔ `pop` 반전 | orange / yellow / red | 무늬 없이 면 분할(그레인과 옅은 `stagelight`만) | 아주 큰 굵은 글자, 기울임 |
| 금융·데이터·리포트 | `night` | mint / amber | `gridlines` 옅게 | 숫자는 Geist, 표·라벨 정돈 |
| 감성·스토리·시상 | `night` 또는 `ink` | amber / white | `glow` + `particles` + `letterbox` | 세리프 이탤릭 한 단어 혼합 |
| 프리미엄·럭셔리 | `ink` | white(무채) 또는 amber | `horizon` 가늘게 | 얇은 굵기 + 넓은 자간 라벨 |
| 밝고 친근(학생·생활) | `white` | pink / orange / mint | `stagelight`(아주 옅게) + 부드러운 그림자 | 둥근 칩·카드 위주 |

기본값이 고민되면: **`ink` + `blue` + `stagelight` + `horizon` + `grain` + `vignette`**.

## 7. 연속성 사전 — 무엇이 무엇으로 이어지나

| 앞 장면의 것 | 뒤 장면에서 되는 것 |
|---|---|
| 점(상태 표시·커서 파문) | 로고의 일부, 라벨 앞의 점, 차트의 첫 점 |
| 입력창 | 카드(아래로 자람), 검색 결과 창, 말풍선 |
| 친 문장 | 카드의 제목, 큰 헤드라인 |
| 진행 막대 | 숫자 아래의 기준선, 차트의 축, 밑줄 |
| 큰 숫자의 0·O | 통과하는 구멍(줌 스루), 원형 진행 링 |
| 카드 한 장 | 화면 전체(확대), 폰 화면(풀백), 격자의 한 칸 |
| 버튼 | 다음 장면을 여는 와이프의 출발점(아이리스 중심) |
| 선 | 차트의 선, 타임라인, 구분선, 형광펜 |
| 강조된 단어 | 다음 장면의 제목 |

트리트먼트의 "전환" 칸에는 이 표에서 고른 쌍을 적는다. 쌍이 떠오르지 않으면 `wipe`·`zoom`을 쓴다.

## 8. 화면 문구 규칙

- 사용자의 문장을 **화면용으로 줄인다**: 조사·수식어를 덜고 명사와 수로. "수업 준비 시간이 확 줄어듭니다" → "120분 → 10분".
- 제목은 2줄 이내, 세로 화면 한 줄 12자·가로 화면 18자 안팎. 줄은 의미 단위로 끊는다(`<br>`).
- 한 비트에 문구 블록은 최대 3개(라벨·제목·보조). 그 이상이면 비트를 나눈다.
- 숫자에는 단위를 작게 붙인다(`120`**분**). 날짜·이름은 사용자가 준 그대로.
- UI 속 글(버튼·플레이스홀더)은 실제 서비스처럼 짧고 구체적으로: "무엇이든 맡겨 보세요", "연수 신청하기".
- 영문 모노 라벨(`AGENT · RUNNING`, `01 / 05`)은 **질감**이다. 내용은 한글 문구가 전달한다.

## 9. 트리트먼트 템플릿

```
요청      (사용자의 말 그대로)
메시지    한 문장
형식      1080×1920 · 13초 · 30fps · 쇼츠 · 템플릿 hook (+ 재료: 참고 영상 분석 / brand.json / 음악 BPM / 자막 파일)
로그라인  [주체]가 [동사]해 [결과]가 된다
룩        ink · blue · stagelight+horizon · Pretendard 굵게/모노 라벨 · grain
비트      0.0–2.9  훅 — "120분"이 솟고 "아직도 직접 하세요?"(‘직접’ 형광펜). 카메라: 비스듬→정면
          2.9–6.0  요청 — 입력창 등장, 커서 클릭, "3학년 과학 활동지 만들어줘" 타이핑, 전송
          6.0–9.1  실행 — 입력창이 카드로 자람, 세 단계 스피너→체크, 진행 막대
          9.1–12.6 결과 — 막대가 내려와 120 → 10 카운트와 함께 줄어듦, "110분을 돌려받습니다"
          12.6–15.5 엔드카드 — "AI에게 일을 맡기는 교사" + "연수 신청하기", 커서 클릭
카메라    훅 정착 → 입력창 푸시 인+오빗 → 카드 오빗 → 정면 정착. 전체 드리프트 1.05
전환      숫자 0 줌 스루 · 입력창→카드 · 진행 막대→기준선 · 남은 막대→라벨의 점
소리      효과음 6곳 — 2.9 whoosh(입력창 등장) · 4.3 key(타이핑) · 5.9 click(전송) · 8.6 success(체크) · 12.6 swell → 13.4 click(엔드카드). 음악은 받지 않았으므로 없음
모션      등장 mo.out, 퇴장 mo.in 0.4초, 카메라 mo.cam, 체크만 mo.spring. 포인트는 한 프레임 한 곳
합격 기준  0초 프레임에 숫자가 이미 보인다 · 결과 숫자 1.2초 정지 · 엔드카드 2초 이상 · 커서가 실제로 버튼 위 · check 오류 0 · score 85+
```

**합격 기준**은 "잘 만들었다"의 정의다. 막연한 "고급스럽게" 대신 시트와 점수로 확인할 수 있는 문장으로 쓴다:
- 시간: "결과 숫자 1.2초 정지", "엔드카드 2초", "모든 컷이 박 위(±1프레임)"
- 화면: "0초 프레임을 포스터로 쓸 수 있다", "포인트 색은 한 프레임에 한 곳", "자막과 제목이 겹치지 않는다"
- 사실: "날짜·이름·수치가 사용자의 글자 그대로", "예시 수치에는 (예시)"
- 반복 영상: "마지막 프레임 = 첫 프레임"
렌더 뒤에는 이 문장들을 하나씩 대조한다(시트·프레임 띠·`motion score`).

사용자에게는 이 중 **로그라인·룩·비트**만 짧게 보여 주고 바로 제작에 들어간다(승인을 기다리느라 멈추지 않는다. 사용자가 "먼저 구성만"이라고 했을 때만 멈춘다).

## 9-1. 재료를 먼저 잰다

사용자가 무언가를 함께 줬다면 트리트먼트보다 측정이 먼저다. 감으로 쓰지 않는다.

| 재료 | 명령 | 트리트먼트에 들어가는 것 |
|---|---|---|
| 참고 영상 | `motion analyze 참고.mp4` | 평균 샷 길이 → 비트 길이 · BPM · 테마/포인트 색 제안 · 샷 시트를 보고 적은 구도·전환 방식 |
| 브랜드 사이트 | `motion brand https://…` | 테마 · 포인트 색 · 이름 · 한 줄 소개(사이트의 말 그대로) · 로고 |
| 음악 | `motion audio 노래.mp3` | BPM · 마디 첫 박 시각 → 큰 변화의 자리 |
| 대본·녹음 | `motion captions plan` / `align` | 문장 시각 → 비트 시트, 자막 스타일 |
| 표 | (완성 뒤) `motion batch` | 바뀌는 칸 → `data-var` |

## 9-2. 안을 여러 개 보여 줄 때

사용자가 "몇 가지 버전"을 원하면 같은 메시지로 **서로 다른 안 2–3개**를 짧게 제시한다. 각 안은 3줄: 로그라인 · 룩(테마·포인트 색·빛) · 결정적 장면(예: "숫자 0을 뚫고 들어간다"). 안끼리는 구조가 달라야 한다(색만 다른 세 안은 한 안이다). 사용자가 고르면 그 안으로 트리트먼트를 쓴다. 요청하지 않았으면 하나를 골라 바로 만든다.

## 10. 예시 — 요청에서 트리트먼트까지

**A. "우리 학교 가을 운동회 홍보 영상 오프닝 만들어줘. 10월 23일 금요일이야."**
```
메시지    10월 23일, 운동회가 열린다
형식      1080×1920 · 9초 · 128 BPM
로그라인  박자마다 단어가 화면을 때리다가 날짜 하나로 수렴한다
룩        ink ↔ pop(orange) 반전 · 면 분할 · 아주 큰 기울인 글자 · 트랙 라인(가는 흰 선) 모티프
비트      0–0.47   "READY" 슬램(검정)
          박마다    "달리고" → "던지고" → "넘고" → "함께" — 하드컷, 3번째 컷만 pop 배경
          3.3–5.2  트랙 라인 여섯 줄이 왼→오로 그려지고 그 위로 "가을 운동회"가 휩 팬으로 들어옴
          5.2–7.2  날짜 "10.23" 오도미터 + "FRI" 라벨(요일은 사용자가 준 것), 착지에 펄스
          7.2–9.0  "10월 23일 금요일" 한 줄. 홀드 — 학교명·연도는 받지 않았으니 넣지 않는다
카메라    컷마다 1.04 펀치 인, 마지막에 느린 푸시
전환      cut(박자) → whip → 트랙 선이 날짜의 밑줄이 됨
```

**B. "학생 참여율이 62%에서 96%로 올랐다는 걸 보여주는 발표용 화면"**
```
메시지    참여율이 96%가 됐다
형식      1920×1080 · 7초
로그라인  62에 머물던 링이 96까지 차오르며 숫자가 따라 오른다
룩        night · mint · gridlines 옅게 · 숫자 Geist
비트      0–1.0   라벨 "학생 참여율" + 회색 링 62%에서 정지("전년" 같은 기간 표시는 받지 않았으니 "BEFORE"까지만)
          1.0–3.4 링이 mint로 96%까지, 가운데 숫자 62 → 96 카운트(같은 이징). 카메라 푸시 인
          3.4–4.2 착지 펄스, "+34%p" 칩 pop(62와 96에서 계산되는 값이라 써도 된다)
          4.2–7.0 "62%에서 34%p 올랐습니다" 한 줄 · 홀드 — 원인·기간처럼 받지 않은 설명은 덧붙이지 않는다
```

**C. "앱 로고 나오는 3초짜리 엔딩"**
```
로그라인  점 하나가 켜지고 원으로 열려 로고가 드러난다
비트      0–0.5 점 pop / 0.5–1.4 iris로 심벌 드러남, 카메라 살짝 풀백 / 1.2–2.2 이름이 타자 치듯 / 2.2–3.0 홀드
```
로고 파일을 받지 못했으면 **이름의 타이포 워드마크**로 만든다(로고를 지어내지 않는다).

**D. "회의록을 AI가 요약해 주는 기능 소개, 유튜브 영상에 넣을 6초 컷"**
```
형식      1080×830 인서트(기기 틀 없음)
비트      0–1.0  긴 회의록 문서(스켈레톤 줄 12개)가 보인다
          1.0–2.4 커서가 "요약" 버튼으로, 클릭
          2.4–4.4 문서의 줄들이 위로 접히며 세 줄로 수렴, 한 줄씩 또렷해짐
          4.4–6.0 마지막 줄에 형광펜, 라벨 "12줄 → 3줄" 정지
```

## 11. 예시에 없는 장면 만들기

어떤 요청이든 다섯 가지로 분해한다.

| 분해 | 묻는 것 | 예: "나무가 자라는 걸로 성장 표현해줘" |
|---|---|---|
| 주체 | 화면의 주인공 하나 | 선 하나(줄기) |
| 공간 | 어디에 놓이나, 깊이는 | 종이색 여백, 바닥선 |
| 변화 | A → B | 선이 위로 자라며 가지로 갈라지고 끝마다 점(잎)이 켜진다 |
| 카메라 | 무엇을 따라가나 | 자라는 끝을 따라 틸트 업 → 풀백으로 전체 |
| 리듬 | 빠르기·쉼 | 가지가 갈라질 때마다 반 박 쉼, 마지막에 수치 등장 |

그리고 **엔진의 프리미티브로 번역**한다.

| 필요한 것 | 프리미티브 |
|---|---|
| 사물·자연물 | 기하 도형(원·선·사각)의 조합, SVG `path` + `draw`, 단색 실루엣. **만화풍 클립아트를 그리지 않는다** |
| 사람 | 아바타 원(`mo-avatar`), 커서 이름표, 실루엣 아이콘(`users`, `person-standing`). 얼굴·몸을 그리지 않는다 |
| 장소 | 지도 대신 점+선+라벨, 건물 대신 아이콘 타일 |
| 실사 느낌 | 사용자가 준 사진·영상을 `mo-media`에 넣고 켄 번스 + 타이포. 없으면 추상으로 간다 |
| 물리 효과(폭죽·비·눈) | `M.onFrame`으로 캔버스에 시드 고정 입자 |
| 손그림 느낌 | SVG 선 + `draw`, 끝을 둥글게 |
| 소리의 표현 | 박자에 맞춘 막대·파형(`M.onFrame`으로 높이 계산) |

추상화의 기준: **픽토그램 수준에서 멈춘다.** 디테일을 그릴수록 유치해진다. 형태는 단순하게, 움직임과 빛과 타이포로 품질을 만든다.

마지막으로 스스로 묻는다: *"이 장면에서 한 장면만 캡처해 포스터로 걸어도 되는가?"* — 아니라면 구도·여백·글자 크기부터 다시 잡는다.
