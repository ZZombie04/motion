# 참고 사이트 분석 — "따라 만드는 모션그래픽 160"

분석 대상: <https://www.careerhackeralex.com/sharings/cha-motion-kit> (Career Hacker Alex, 2026-10-03 업데이트판)
분석일: 2026-10-05 · 방법: 공개 페이지의 목록·상세 화면과 각 모션에 붙은 "따라 만들기 프롬프트" 160건을 읽고 구조·어휘·수치를 집계.

> 이 문서는 **방법론의 분석**이다. 원문 프롬프트·영상·편집 소스는 이 저장소에 포함하지 않았다(해당 사이트의 저작물). 이 스킬의 엔진·문서·샘플은 분석에서 얻은 원리를 바탕으로 새로 작성했다.

## 1. 무엇이 있는가

| 분류 | 개수 | 내용 |
|---|---:|---|
| 화면 속 작업 | 20 | 기기 틀 없이 UI 안에서 타이핑·선택·연결·편집의 조작과 결과 |
| 창작 변환 | 21 | 프롬프트 → 이미지 → 움직임 → 타이포로 이어지는 변환 |
| 녹화·설명 | 20 | 실제 화면 녹화를 확대·이동하거나 과정·선택 기준을 설명 |
| 모션 용어 | 25 | 용어 21개를 실제 움직임으로 + 기법 조합 4종 |
| 필름 | 5 | 13–16초 세로 광고(원테이크 포함) |
| 컴포넌트 | 17 | 폰·노트북·창·채팅·터미널 데모 |
| 기법 | 20 | 3D 카메라·원근·깊이 |
| 트랜지션 | 9 | 장면을 끊김 없이 잇는 전환 |
| 타이포그래피 | 23 | 글자가 움직이며 메시지를 전함 |
| **합계** | **160** | 길이 3–16.8초(평균 6.4초) · 1080×830 인서트가 기본, 필름은 1080×1920 |

구현 방식: 160건 중 **156건이 HTML+GSAP**, 4건이 Blender(3D 제품 컷). 각 모션에 MP4와 "AI에게 붙여 넣는 프롬프트"가 함께 제공된다.

## 2. 핵심 방법 — 프롬프트의 해부

프롬프트는 거의 같은 뼈대를 가진다.

1. **로그라인 한 문장** — 무엇이 어떻게 되는 장면인지 + 구현 방식 + 캔버스·길이(+BPM/fps).
2. **룩** — 배경색, 포인트 색과 그 사용처(한 곳), 글꼴과 굵기, 모서리의 작은 모노 라벨.
3. **타임코드 비트** — `0–0.5초: …`, `0.5–1.4초: …`처럼 절대 시각으로, 화면에 보일 **실제 문구**와 **구체적 수치**(각도·배율·간격)까지 적는다.
4. **모션 감각 한 줄** — "끊기지 않게 이어지고, 등장은 빠르게 나와 부드럽게 감속, 카메라는 천천히 가감속, UI는 살짝 튕기듯".

후기 61건(화면·창작·녹화)에는 엔지니어링 조건이 추가된다.

- **일시정지된 GSAP 타임라인 하나**로 만들고 임의 시점으로 이동해도 같은 화면이 나오게(결정성).
- 시계·무작위·네트워크 호출 금지, 로컬 글꼴, 문구·이미지는 변수로 교체 가능.
- 4단 타이밍: 0초 입력 상태를 읽을 수 있게 → 1.0초 조작 시작 → 3.2초 결과 연결 → 5.4초 정리·유지.
- 끝 상태 라벨을 0.8–1초 이상 읽게.
- "설명용 재연"임을 표시하고, 실제 성능·로고·수치를 꾸며내지 않는다.

## 3. 디자인 체계

| 요소 | 규칙 | 근거(160건 본문 집계) |
|---|---|---|
| 색 | 잉크 `#0A0A0A` · 페이퍼 `#F4F3EE` · 라임 `#D4F527` | 라임 240회, 잉크 115회, 페이퍼 43회 언급 |
| 포인트 색 | **한 화면에 한 곳만**(형광펜·버튼·점·진행 막대 중 하나) | "한 곳만/하나만" 표현이 거의 모든 프롬프트에 등장 |
| 글꼴 | Pretendard(한글) + Geist(영문·숫자), 굵기 400–600 | Pretendard 101회, Geist 56회 |
| 라벨 | 모서리의 작은 회색 모노 대문자(`CHA · DEMO 01`, `01 / 06`) | "모노" 100회 |
| 강조 | 형광펜이 왼→오로 칠해지며 글자색이 함께 바뀜 | "형광펜" 41회 |
| UI | 로고 없는 일반화된 폰·노트북·창, 커서의 원인→결과 | "커서" 61회 |

## 4. 모션 문법

| 원리 | 표현 | 빈도 |
|---|---|---:|
| 연속성 | "움직임은 끊기지 않게 이어지고" | 34 |
| 감속 중심 | "빠르게 나와 부드럽게 감속(expo.out)" / "가감속(ease-in-out)" | 감속 71 |
| 순차 등장 | "차례로" | 43 |
| 절제된 튕김 | "살짝 튕기듯" — UI·칩·카드에만 | 64 |
| 멈추지 않는 화면 | "아주 천천히 다가간다/커진다/흐른다" | 천천히 67 |
| 박자 | BPM(96·120·128)에 컷과 단어를 맞춤 | 27 |
| 깊이 | "3D 원근으로 비스듬히", 줌인/줌아웃, 마스크 | 3D 35 · 줌 30 · 마스크 19 |

**카메라 어휘**(기법·트랜지션 29건에서): 푸시 인, 풀백 리빌, 오빗(60–70°), 트럭+패럴랙스, 슬랜트 돌리, 랙 포커스, 휩 팬+스피드 램프, 줌 스루, 아이소 벽에서 하나 들어 올리기, 스포트라이트 리프트, 드로스테 무한 줌, 원형 마스크(아이리스), 매치 컷, 카드 스택 스와이프, 기기 뒤집기, 창 분할 그리드.

**연결의 원리**: 필름 5건은 "모든 전환은 같은 도형이 다음 장면으로 이어지는 방식"으로 쓰여 있다(점 → 앱 아이콘 → 화면 → 폰 → 노트북 창 → 선 → 로고의 렌즈). 컷 대신 **변신**.

**용어 21개**: 이징, 예비동작, 스쿼시 앤 스트레치, 아크, 팔로스루, 오버랩, 스태거, 매치컷, 패럴랙스, 마스크 리빌, 모션 블러, 홀드, 세컨더리 액션, 줌 스루, 휩 팬, 아이리스, 키네틱 타이포, 카운트업, 푸시 인, 비트 싱크, 루프 — 그리고 이들을 4개씩 겹친 조합 예제(타이틀 등장·카드 넘기기·숫자 강조·통통 튀는 등장).

## 5. 사이트 방식의 한계와 이 스킬이 더한 것

| 사이트 방식 | 한계 | 이 스킬 |
|---|---|---|
| 사용자가 160개 중 골라 프롬프트를 복사·수정 | 기법 이름과 구조를 사용자가 알아야 함. 목록에 없는 장면은 직접 설계 | **리프롬프트**: 평범한 요청을 감독처럼 해석해 구조·카메라·전환을 스스로 고른다(`references/director.md`, `motion_brief`) |
| 매번 AI가 HTML을 처음부터 작성 | 타이핑·커서·마스크·기기 등 어려운 부분의 품질이 들쭉날쭉 | **엔진**: 한글 자모 타이핑, 휜 경로의 커서, 마스크 리빌, 3D 카메라·깊이·랙 포커스, 두께 있는 기기를 검증된 부품으로 제공 |
| 결과 확인은 사람이 재생해 보며 | AI가 자기 결과를 보지 못함 | **자동 점검 + 프레임 검수**: 겹침·잘림·가독성·정지 구간을 측정하고, 콘택트 시트를 AI가 직접 보고 고친다 |
| 모션 블러는 흐림·잔상으로 흉내 | 빠른 이동에서 어색 | **실제 셔터 모션 블러**: 프레임 안을 최대 16번 나눠 찍어 선형광으로 합성(움직임이 빠른 프레임만) |
| 단일 하우스 스타일(잉크·페이퍼·라임) | 다른 톤의 요청에 그대로 쓰기 어려움 | 5개 테마 × 포인트 색, 분야별 룩 표(`references/look.md`) |
| MP4 내려받기 | 재렌더·비율 변경은 별도 작업 | CLI·MCP로 mp4·gif·webm·투명 mov, `--vars`로 문구 교체 |

## 6. 그대로 이어받은 원칙

- 결정적 단일 타임라인(임의 시점 탐색 = 프레임 정확 렌더)
- 포인트 색은 한 프레임에 한 곳
- 타임코드 비트 시트를 먼저 쓰고 만든다
- 끊기지 않는 카메라와 끝까지 흐르는 느린 움직임
- 같은 물체가 다음 장면으로 이어지는 전환
- 끝 상태를 읽을 시간, 정직한 표현(지어낸 로고·수치 금지)
