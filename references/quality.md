# 검수 — 보고, 비평하고, 고친다

코드를 다 썼다고 끝난 것이 아니다. **렌더된 화면을 직접 보기 전에는 완성이 아니다.**
순서: `motion check`(기계가 재는 것) → `motion sheet`(흐름을 눈으로) → `motion frames`(핵심 장면을 원본 크기로) → 고치기 → 다시.

## 1. `motion check` — 코드별 뜻과 고치는 법

| 코드 | 수준 | 뜻 | 고치는 법 |
|---|---|---|---|
| `page` | 오류 | 콘솔 오류, 파일 누락(404) | 경로는 컴포지션 폴더 기준 상대 경로. 외부 URL 금지 |
| `overlap` | 오류 | 정지한 두 글자 블록이 겹침 | 앞 요소를 `M.exit`으로 먼저 내보내거나 위치·크기 조정. 장면 창(`M.scene`)의 끝 시각이 다음 등장보다 늦지 않은지 확인 |
| `clipped` | 오류 | 글자가 화면 밖으로 잘림 | 크기를 줄이거나 줄바꿈, `--safe-x` 안으로. 카메라 `zoom` 때문에 밀려났다면 배율을 낮춘다 |
| `static` | 오류 | 처음부터 끝까지 변화 없음 | 타임라인에 트윈이 없다 — `Motion.compose` 콜백과 선택자를 확인 |
| `masked` | 경고 | 글자가 부모에 가려 일부만 보임 | 부모의 `overflow`·높이, 마스크 리빌이 끝까지 가는지 |
| `tiny` | 경고 | 글자가 휴대폰에서 읽기 어려운 크기 | 본문 3u·라벨 1.6u 이상. 기기 화면 속 UI는 카메라로 확대해 보여 준다 |
| `contrast` | 경고 | 글자와 바탕의 대비 부족 | `--fg-2`/`--fg-3`까지만. 포인트 색 위는 `--on-accent` |
| `short-read` | 경고 | 읽기 전에 사라짐 | 머무는 시간을 늘리거나 문구를 줄인다 |
| `late-entry` | 경고 | 끝나기 직전에 새 요소 등장 | 마지막 요소는 끝 1초 전에 정착. 또는 `data-duration` 연장 |
| `late-start` | 경고 | 첫 0.7초 넘게 볼 것이 없음 | 첫 트윈을 0초에, 시작값을 "이미 들어오는 중"으로 |
| `frozen` | 경고 | 0.7초 이상 화면이 완전히 정지 | `cam.drift`, `cam.float`, `M.float` |
| `safe-area` | 경고 | 쇼츠 UI에 확실히 가려지는 위치(상단 7%·하단 16%·우측 버튼 줄) | 핵심은 `.mo-safe`(상단 10.5%–하단 20%) 안. 미리보기에서 G, 시트는 `--guides` |
| `soft` | 경고 | 기울어진 화면을 3.3배 넘게 확대(렌더의 선명 보정 한계) | 요소를 가장 가까운 샷의 크기로 만들고 넓은 샷은 `zoom < 1`, 또는 확대하는 동안 기울기 0 |
| `font` | 경고 | 번들에 없는 글꼴 | 기본 4종을 쓰거나 woff2를 폴더에 넣고 `@font-face` |
| `accent` | 참고 | 포인트 색이 3곳 이상 | 하나만 남기고 흰색·회색으로 |

**오류는 0이 되어야 한다.** 경고는 고치거나, 의도한 것이면 이유를 알고 넘어간다(예: 배경 장식 글자 → `data-deco`를 붙이면 검사에서 빠진다).
타임라인이 `data-duration`보다 길거나 `repeat:-1`이 있으면 check·render 모두 "컴포지션 오류"로 멈춘다 — 메시지대로 고친다.

## 2. 콘택트 시트 보는 법

```
motion sheet work/x.html --count 18                 # 전체 흐름
motion sheet work/x.html --from 2.4 --to 3.4 --count 12   # 전환 구간을 촘촘히(--at 2.4,2.6,… 로 직접 고를 수도)
motion sheet work/x.html --beats 128                # 박자 영상: 박마다 한 장
motion sheet work/x.html --guides                   # 쇼츠 안전영역을 겹쳐서
motion sheet work/x.html --no-camera                # 카메라를 끄고 "쉬는 배치"만(정렬·여백 확인)
motion frames work/x.html --at 1.5,6.8,13.0          # 핵심 비트 원본 크기(--blur 16이면 렌더와 같은 모션 블러)
```

시트의 타일을 **왼쪽 위부터 차례로** 보며 아래를 묻는다. 하나라도 "아니오"면 고친다.

**흐름**
- 첫 타일(0초)에 이미 무언가 있는가? 마지막 2–3타일이 같은 화면(엔드카드 홀드)인가?
- 타일마다 화면이 **충분히 달라지는가**? 비슷한 타일이 5개 이상 이어지면 그 구간이 지루하다(마지막 엔드카드 홀드 2–3타일은 예외).
- 장면 사이에 **빈 타일**이 있는가? 있다면 겹침이 부족하다(다음 장면을 0.2–0.4초 당긴다).
- 전환 중간 프레임이 어색한가(텅 빈 상자, 글자 없는 카드, 잘린 요소)?

**구도**(타일 하나를 포스터라고 생각하고)
- 주인공이 0.3초 안에 눈에 들어오는가? 크기 대비가 분명한가?
- 좌우 여백이 같은가, 덩어리가 한 축에 정렬돼 있는가?
- 비어 있는 곳이 "여백"으로 보이는가, "덜 만든 것"으로 보이는가? (후자면 주인공을 키우거나 위치를 30–60% 높이로)
- 요소가 화면 가장자리에 닿거나 잘리지 않는가? 카메라가 줌인한 구간을 특히 본다.

**글자**
- 폰 크기로 줄여 봐도(시트 타일이 바로 그 크기다) 제목이 읽히는가?
- 한 화면에 글자 덩어리가 3개를 넘지 않는가? 줄바꿈이 의미 단위인가?
- 포인트 색이 한 타일에 한 곳인가?

**디테일**(원본 크기 프레임에서)
- 커서가 실제로 대상 위에 있는가? 클릭 위치가 버튼 안인가?
- 타이핑 문장이 입력창을 넘치지 않는가? 숫자와 단위가 겹치지 않는가?
- 카드 안 여백이 고른가? 아이콘·체크의 크기가 글자와 어울리는가?
- 3D 기울임 중에 글자가 읽히는가(읽혀야 하는 글자는 각도 14° 이내)? `frames`의 스틸은 렌더와 같은 선명도다 — 여기서 흐리면 결과물도 흐리다.

## 3. 흔한 문제와 처방

| 증상 | 원인 | 처방 |
|---|---|---|
| 시작하자마자 요소가 잠깐 보였다 사라짐 | 여러 `fromTo`가 같은 속성을 초기화 | 뒤쪽 트윈에 `immediateRender: false`, 또는 `to`로 이어 붙이기 |
| 장면이 바뀔 때 두 제목이 겹침 | 앞 장면의 `M.scene` 끝이 늦거나 퇴장이 없음 | 퇴장을 0.3초 앞당기고 끝 시각을 맞춘다 |
| 커서·탭이 엉뚱한 곳을 누름 | 대상이 회전한 기기 안, 또는 `display:none` 상태에서 측정 | 커서를 화면에 붙인다(`M.cursor({ parent: '… .mo-screen' })`). `M.tap`은 화면 속 대상이면 자동. 그 밖엔 `motion probe`로 좌표 확인 후 `{ x, y }` |
| 줌인하자 좌우가 잘림 | 요소 폭 × zoom > 화면 폭 | zoom을 낮추거나 요소 폭을 줄인다(폭 900이면 1.18배까지) |
| 3D 회전이 납작하게 보임 | 조상이 3D 맥락을 끊음 | 회전 요소를 `.mo-world` 가까이에 두거나 조상에 `data-3d` |
| 깊이 레이어가 안 보임 | 불투명한 부모 뒤로 들어감 | 엔진이 자동 처리하지만, 레이어는 장면의 **직계**로 둔다 |
| 화면이 뚝뚝 끊김 | 동작 사이에 공백, 카메라가 정지 | 겹침 0.2–0.4초, `cam.drift` |
| 전체가 밋밋함 | 크기 대비 부족, 빛 없음, 모두 같은 타이밍 | 주인공을 1.5배, 배경에 `horizon`/`glow`, 스태거와 카메라 정착 추가 |
| 유치해 보임 | 색·튕김·일러스트 과다 | look.md §1 표대로 덜어 낸다 |
| 글자가 흐릿함 | ① `will-change`/`filter`가 남아 있음 ② 기울인 채 확대(미리보기에서만) | ① 속성 자체를 없앤다(`blur(0px)`도 남기지 않는다) ② `frames`로 확인 — 렌더는 자동으로 선명하게 찍는다. `soft` 경고가 뜨면 요소를 키운다 |
| 미리보기와 렌더의 선명도가 다름 | 렌더는 기울인 확대 구간을 2–3배로 찍는다 | 정상. 판단은 `frames`·`render` 결과로 한다 |
| 숫자가 흔들림 | 고정폭 아님 | `M.count`/`mo-num` 사용, 단위는 별도 요소 |
| 렌더가 느림 | 큰 `backdrop-filter`·`filter: blur`가 매 프레임 움직임 / 영상 내내 기울인 채 확대 | 유리는 작은 면적에만, 블러는 전환 순간에만. 확인용은 `--quality draft`, 선명 보정을 끄려면 `--no-sharp` |
| 렌더 결과에 `보정 생략 N프레임` | 크게 찍은 화면이 원래 화면과 달라(대개 메모리 부족) 일반 캡처로 대체됨 | 영상은 정상이다(그 구간만 덜 선명). 더 선명하게 하려면 `MOTION_TILE_MB`를 늘리거나 3D 층(기기 옆면 조각 등)을 줄인다 |

## 4. 납품 전 체크리스트

- [ ] `motion check` 오류 0, 경고는 모두 확인
- [ ] 시트로 전체를 봤고, 고친 뒤 **다시** 봤다
- [ ] 0초 프레임에 훅이 있다 · 마지막 1초는 정지된 엔드 상태다
- [ ] 핵심 문구·수치가 1초 이상 읽힌다
- [ ] 포인트 색은 프레임당 한 곳 · 글꼴은 번들 4종 안
- [ ] 사용자가 준 이름·날짜·수치가 **한 글자도 틀리지 않았다**(시트에서 직접 대조)
- [ ] 지어낸 로고·브랜드·실적이 없다(예시 수치는 표시)
- [ ] 쇼츠라면 안전영역 안 · 가로라면 아래위 8% 여유
- [ ] `--quality standard` 이상으로 렌더했고 파일이 재생된다(렌더 결과 줄에 경고가 없는지 확인)

## 5. 전달할 때

파일 경로와 함께 **세 줄**이면 충분하다: ① 무엇을 만들었나(길이·비율) ② 연출의 핵심 한 줄(예: "입력창이 카드로 자라고, 진행 막대가 120분→10분으로 줄어듭니다") ③ 바로 바꿀 수 있는 것(문구·색·길이·비율·음악). 기법 이름을 나열하지 않는다.
